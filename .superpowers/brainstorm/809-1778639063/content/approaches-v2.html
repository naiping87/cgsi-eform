架构方案对比

两种可行的技术架构，各有优缺点

A

单一 Next.js 应用（推荐）

一个代码库搞定前后端：React 页面 + API Routes 处理 PDF 和邮件。部署到 Vercel。

优点

  • 只有一个项目，开发和部署简单
  • Vercel 免费额度足够日常使用
  • API Routes 直接处理，无需跨域

缺点

  • Vercel 免费版 API 超时 10 秒
  • Serverless 文件系统不可靠
B

前后端分离

React 前端部署 Vercel + Express 后端部署 Railway。后端独立处理 PDF 和邮件。

优点

  • 后端无超时限制，大 PDF 也能处理
  • 可靠的文件系统
  • 前后端独立，扩展灵活

缺点

  • 两个项目，两个部署
  • Railway 免费额度有限
  • 需要处理跨域 CORS

我的推荐：方案 A — 单一 Next.js 应用

理由：你的 PDF 都不是特别大，PDF 生成在 10 秒内可以完成。一个项目更简单，Vercel 部署零成本。如果以后遇到超时问题，再迁移到方案 B 也很容易。
